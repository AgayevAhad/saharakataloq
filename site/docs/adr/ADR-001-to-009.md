# Architecture Decision Records (ADR-001 – ADR-009)

## Sahara Electronics Platform

---

### ADR-001: Çoxbrendli Dinamik Brend İdarəetmə Arxitekturası

- **Status:** Qərar verildi (Stakeholder Qərarı #5 ilə uyğunlaşdırıldı)
- **Kontekst:** Platformanın təkcə ARDO üçün deyil, admin tərəfindən idarə olunan çoxbrendli (hazırda ARDO, Lotus, Artel) elektronika platformasına çevrilməsi tələb olunur.
- **Qərar:** Kod bazası "brand-agnostic" arxitekturaya keçirilir. Yalnız bazada mövcud və admin tərəfindən aktiv edilən brendlər public ola bilər. Təsdiqlənməyən brendlər (Samsung, Bosch və s.) özbaşına public edilmir, yalnız namizəd (candidate) kimi saxlanıla bilər.
- **Nəticə:** Yeni brend əlavə edildikdə heç bir frontend kod dəyişikliyi tələb olunmur (tamamilə DB/Admin əsaslıdır).

### ADR-002: İkili SQLite Bazası (Draft/Published) və İmmutable Snapshot Sistemi

- **Status:** Qəbul edildi (Texniki Arxitektur Qərar)
- **Kontekst:** Admin panelində edilən dəyişikliklərin public müştərilərə dərhal təsir etməməsi və səhvlər zamanı təcili geri qayıtma imkanı lazımdır.
- **Qərar:** İki ayrı baza saxlanılır: `catalog-draft.sqlite` və `catalog.sqlite`. Bütün redaktələr qaralamaya yazılır. "Təsdiqlə və Dərc Et" əməliyyatı zamanı avtomatik snapshot arxivi yaradılır və atomik transaction ilə dərc olunur.
- **Nəticə:** Sıfır məlumat itkisi, təhlükəsiz eksperiment və tək kliklə rollback.

---

### ADR-003: 1:1 Pixel-Perfect Skeleton Loading və Pill Naviqasiyası

- **Status:** Qəbul edildi (Texniki Arxitektur Qərar)
- **Kontekst:** Səhifə yüklənərkən tullanmalar (CLS) və kobud sıçrayışlar istifadəçi təcrübəsini pozur.
- **Qərar:** Hər bir komponent üçün real kontentin hündürlüyünə və padding-lərinə 1:1 uyğun gələn `.skeleton-card` və `ShimmerImage` yer tutucuları təyin edilir. Üfüqi kateqoriya pill-ləri seçildikdə mərkəzə yumşaq şəkildə scroll olunur.
- **Nəticə:** CLS < 0.05, 60fps axıcı animasiya və lüks açılış hissi.

---

### ADR-004: Ticarət Modeli və Mərhələli İnkişaf

- **Status:** Qərar verildi (Stakeholder Qərarı #1 ilə uyğunlaşdırıldı)
- **Kontekst:** E-ticarət modelinin biznes risklərini minimuma endirmək və real əməliyyat modelinə uyğunlaşmaq.
- **Qərar:**
  1. İlkin mərhələ: "WhatsApp konsultasiyası + zəng + mağazadan təhvil üçün müraciət" modeli ilə işləyir.
  2. Onlayn bank kartı ödənişi və checkout arxitekturası gələcəyə hazır layihələndirilir, lakin feature flag (`checkout_enabled: false`) ilə deaktiv saxlanılır.
  3. Təsdiqlənməmiş qiymət, stok və taksit məlumatı göstərilmir.
- **Nəticə:** Dəqiq, risksiz və şəffaf müştəri təcrübəsi.

### ADR-005: 1:1 Dəqiq Media Uyğunluğu və Təyin Edilməmiş Fayl Nəzarəti

- **Status:** Qəbul edildi (Texniki Arxitektur Qərar)
- **Kontekst:** Məhsul şəkillərinin kateqoriya və ya təxminlə məhsullara bağlanması səhv fotoşəkillərin müştəriyə göstərilməsinə səbəb ola bilər.
- **Qərar:** Şəkillər və videolar yalnız fayl adında model kodu 1:1 dəqiq uyğun gəldikdə bağlanır. Qalan bütün fayllar təyin edilməmiş qalır və hesabatda bildirilir.
- **Nəticə:** 100% dəqiq məhsul vizualları və sıfır səhv nümayiş.

---

### ADR-006: Müşahidəolunma (Observability) və PII-siz Analitika Hadisələri

- **Status:** Qəbul edildi (Texniki Arxitektur Qərar)
- **Kontekst:** İstifadəçi davranışlarını izləyərkən şəxsi məlumatların (PII - telefon, ad, ünvan) sızması və qanunvericilik pozuntusu riski var.
- **Qərar:** Bütün analitika hadisələri anonim saxlanılır. Telefon nömrələri və adlar analitika cədvəlinə yazılmır; yalnız aqreqasiya edilmiş baxış və klik sayları toplanır.
- **Nəticə:** Məlumatların qorunması standartlarına tam uyğunluq.

---

### ADR-007: Dinamik Çoxsaylı Mağaza və Filial Arxitekturası

- **Status:** Qərar verildi (Stakeholder Qərarı #2 ilə uyğunlaşdırıldı)
- **Kontekst:** Heç bir hardcode və ya təxmin edilən ünvan göstərilməməli, yalnız admin paneldən daxil edilən və aktiv edilən ünvanlar idarə olunmalıdır.
- **Qərar:** Limitsiz filial modeli (ad, dəqiq ünvan, nömrələr, xəritə linki, iş saatları, qeydlər) verilənlər bazasından idarə olunur. Ünvan daxil edilmədikdə təmiz "Ünvan məlumatı tezliklə əlavə ediləcək" placeholder-i göstərilir.
- **Nəticə:** Saxta məlumatların tam aradan qaldırılması və mərkəzləşdirilmiş idarəetmə.

---

### ADR-008: Təsdiqlənmiş Zəmanət və Servis Siyasəti

- **Status:** Qərar verildi (Stakeholder Qərarı #3 ilə uyğunlaşdırıldı)
- **Kontekst:** Hardcode və təsdiqlənməmiş zəmanət müddətlərinin ("3 il ARDO", "1-2 il Lotus") və xidmət iddialarının qadağan edilməsi.
- **Qərar:** Heç bir zəmanət müddəti və ya sertifikat iddiası hardcode edilmir. Zəmanət brend və məhsul səviyyəsində admin paneldən daxil edilir; boş olduqda müddət göstərilmir.
- **Nəticə:** Təsdiqlənməmiş hüquqi və marketinq iddialarının tam təmizlənməsi.

---

### ADR-009: Çoxdilli Arxitektura və İlkin `az` Dili Təyinatı

- **Status:** Qərar verildi (Stakeholder Qərarı #4 ilə uyğunlaşdırıldı)
- **Kontekst:** Keyfiyyətsiz avtomatlaşdırılmış tərcümələrin qarşısını almaq.
- **Qərar:** Arxitektura `az`, `ru`, `en` üçün modular i18n strukturunda qurulur, lakin rəsmi keyfiyyətli tərcümələr hazır olana qədər public dil seçicisi yalnız Azərbaycan dili (`az`) ilə məhdudlaşdırılır.
- **Nəticə:** Yüksək mətn keyfiyyəti və gələcək çoxdillilik hazırlığı.
