# Sahara Kataloq Development Guidelines

## Critical Rules for Agents
1. **Strict Dev Branch Rule**: ALWAYS and under all circumstances commit and push changes ONLY to the `dev` branch (`git push origin dev`). NEVER commit or push to `main` without explicit user permission.
2. **No Raw Sample / Example Media on GitHub**: Raw reference media folders like `Foto/` and raw sample file dumps (`File/`) are private source examples/assets. They MUST NOT be committed or pushed to GitHub. Always keep them in `.gitignore`. Only production web-optimized catalog assets (inside `public/media/`) should be served.
3. **Automated Testing**: Always write and execute automated tests for every newly added or modified feature before finishing.
4. **Sticky Desktop Header**: Keep the header fixed/sticky at the top during scrolling with proper z-index and backdrop blur.
5. **Multiple Addresses**: Full support for multiple store/showroom addresses in admin panel, database, and customer-facing components.
6. **Admin Panel Synchronization**: Any new catalog feature, field, setting, brand, address, or model change MUST be fully supported and synchronized in the Admin Panel with intuitive UI, proper contrast, and end-to-end functionality.
7. **Strict Responsiveness, Horizontal Overflow Prevention & Smooth Motion**: Responsiveness on BOTH Desktop (large screens, laptops) and Mobile (phones, tablets, touch devices) must NEVER be broken. Horizontal scrollbars (`overflow-x`) on the page or modal containers are strictly forbidden (`overflow-x: hidden !important`, `max-width: 100% !important`). Touch scrolling must run with zero main-thread layout thrashing (60/120fps smooth native momentum) by using passive listeners and `requestAnimationFrame`. Any "Scroll-To-Top" or anchor navigation action MUST execute a smooth gliding animation (`behavior: 'smooth'`) without instant jump/teleport overrides.
8. **Multi-Brand Promotional & Technology Spotlight Synchronization**: Promotional hero banners, technology highlights, and informational spotlights must actively and dynamically showcase features across all active catalog brands (e.g. ARDO SABAF/Inverter, Lotus Rapid Air/Smart Touch, etc.) with smooth animated rotation, rather than being restricted to a single brand. When new brands or technologies are introduced, these spotlights must automatically support and reflect them.
9. **Admin Panel Data & Image Crop Preservation**: User customizations made via the Admin Panel (including image crop/positioning `objectPosition`, `imagePosition`, `fitMode`, edited specs, custom prices, and descriptions) are sacred. NEVER execute destructive scripts or overwrite `data/catalog.sqlite` and `data/catalog-draft.sqlite` with static seeds that wipe user-customized properties. All import and migration utilities must strictly merge and preserve existing user customizations.
10. **Multi-Brand Dynamic Smart Search & Suggestions**: Search query matching, keyword auto-completions, popular/featured product recommendations, and category tags must dynamically index and reflect ALL active products across all catalog brands (e.g. ARDO, Lotus, and any future added brands) rather than hardcoded or single-brand items. The search dropdown must present a modern multi-column layout (Left: Search suggestions/keywords with query highlighting [8-9 items on desktop, 5 on mobile], Right: Popular/featured product cards with prices and crisp images, Bottom: Quick category navigation pills).
11. **Mandatory 1:1 Pixel-Perfect Skeleton Loading & Shimmer UI Integration**: Any newly introduced or modified catalog section, product grid, media card, search dropdown, brand showcase, banner, or detail modal MUST include and maintain smooth, accessible Skeleton / Shimmer loading placeholders (`Skeletons.tsx`, `.skeleton-box`, `.skeleton-card`, `.img-shimmer-container`, and `shimmerWave` animation). Crucially, Skeleton layouts MUST replicate the exact 1:1 structural anatomy, grid column count (e.g. exactly 3 brand cards matching ARDO/ARTEL/LOTUS with logo shell, copy, and badges; full BannerHero header/spotlight bar; exact ProductCard media/specs/price/button rows), padding, and container heights of the fully loaded components. This strictly eliminates any Cumulative Layout Shift (CLS), jumping, bouncing, or flickering ("atma-təntimə"), ensuring a seamless transition from loading placeholders to loaded content across both Light and Dark modes.
12. **Universal Shimmer Image Loading & Rotating Spinner Animation**: All newly introduced, modified, or rendered image elements across public catalog cards, detail modals, brand marks, category filter bars, search overlays, and admin panels MUST utilize the centralized `ShimmerImage` component (`ShimmerImage.tsx`, `.img-shimmer-container`, `.img-shimmer-overlay`, and `.img-spin`). While an image is downloading/decoding, it MUST display an animated shimmer background with a subtle centered rotating spinner indicator (`Loader2` / `imgSpinAnim`), and upon successful load (`onLoad`), it MUST smoothly fade in with cubic-bezier opacity transition. In case of network failure (`onError`), a clean, branded fallback icon must be rendered without breaking layout.
13. **Fluid Zero-Stutter Mobile Navigation & Performance Integrity**: All scroll event listeners, intersection observers, and header state toggles on mobile touch devices must remain lightweight and non-blocking. Abrupt UI snaps, heavy synchronous `getBoundingClientRect()` loops during active scroll, or layout jumps are strictly prohibited, ensuring a luxurious, app-like scrolling experience.
14. **Universal Horizontal Pill/Chip Touch & Drag Scrolling with Auto-Centering on Selection**: All horizontally arranged category pills, filter rows, media strips, and chip bars (`useHorizontalScroll`, `.filter-row`, `.brand-category-pills-wrap`, `.product-media-strip`, `.smart-search-categories-row`, `.preview-filters`) MUST fully support fluid touch swiping on mobile and grab-to-scroll dragging on desktop without triggering accidental clicks. Crucially, when any pill is clicked, tapped, or programmatically activated, the container MUST smoothly auto-scroll (`behavior: 'smooth'`) to center the active item, ensuring that both the selected pill and adjacent hidden items slide into full view without edge cutoffs.
